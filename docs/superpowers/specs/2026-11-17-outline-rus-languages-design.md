# Outline RU: только en_US и ru_RU

## Зачем

Сборка совпадает с официальным Outline. Отличие — языки `en_US` и `ru_RU` и место, где они подключаются. Официальный релиз вливается merge тега, эта дельта остаётся.

## Цели

- Настоящий fork `attoktist/outline-rus` от `outline/outline`, рабочая копия в `C:\Проекты\OutlineRus`.
- В меню, в `languages`, в `supportedLngs`, в preload и в проверке `DEFAULT_LANGUAGE` только `en_US` и `ru_RU`.
- Русский каталог — перевод значений `shared/i18n/locales/en_US/translation.json` по смыслу.
- После каждого релизного тега новые английские ключи допереводятся, тесты каталога зелёные.

## Не делаем

- Правки продукта Outline.
- Удаление чужих каталогов локалей и чужих локалей дат.
- Перевод хоткеев, плейсхолдеров, разметки и URL.
- Отправку русского в Crowdin.
- Смену `fallbackLng` на клиенте и сервере.
- Смену дефолта в коде: `DEFAULT_LANGUAGE` остаётся `en_US`, пока оператор не задаст `ru_RU`.

## Провал

- Форк, в котором релизный тег конфликтует на десятках файлов локалей.
- Репозиторий без связи fork с `outline/outline`.

## Ограничения

- Текущий `attoktist/outline-rus` — не форк, в нём один README. GitHub не превращает такой репозиторий в fork: README-репозиторий удаляется, на его месте создаётся fork с именем `outline-rus`.
- Ключ перевода — английская строка. Нет значения — клиент показывает ключ. Сервер откатывается на `DEFAULT_LANGUAGE`.
- `shared/i18n/translations.test.ts` требует непустые значения и те же `{{плейсхолдеры}}`, что в ключе. Значение не должно заканчиваться на `_plural`.
- Славянские языки в официальном каталоге записаны двумя ключами i18next v3: без суффикса и с суффиксом `_plural`. Для `ru` этого мало. В режиме `compatibilityJSON: "v3"` i18next выбирает для русского суффиксы `_0` (1, 21, 31…), `_1` (2–4, 22–24…) и `_2` (0, 5–20…). Эти три ключа добавляются рядом с парой из `en_US`. Ключ без суффикса и ключ `_plural` остаются.
- `languageOptions` — единственный список, из которого выводятся `languages`, клиентские `supportedLngs`, серверный preload, маршрут `/locales/:lng.json` и `@IsIn(languages)` у `DEFAULT_LANGUAGE`. Тесты upstream, которые ждут другой код языка, переведены на `ru_RU` или на явный аргумент письма.
- Даты берутся из объекта `locales` в `shared/utils/date.ts`. Для русского нужна локаль `date-fns/locale/ru`.
- Браузер с языком `ru` определяется как `ru_RU` и применяется, только если этот код есть в `languages`.

## Подходы

1. **Merge релизного тега. Выбран.** Массив языков upstream остаётся на месте. `ru_RU` добавляется в конец. Экспорт `languageOptions` — фильтр до `en_US` и `ru_RU`. В `date.ts` добавляется `ru_RU`. Новый файл — `shared/i18n/locales/ru_RU/translation.json`. Чужие каталоги остаются в дереве. `origin` — форк, `upstream` — `https://github.com/outline/outline.git`. Дельта лежит на `main`.
2. **Rebase наших коммитов на каждый тег.** Отклонён: та же дельта, история перевода переписывается, нужен force-push.
3. **Патч поверх архива релиза без форка.** Отклонён: рабочее дерево должно быть форком Outline.

## Как устроено подключение

- В `shared/i18n/index.ts` экспортируемый массив переименовывается в локальный `allLanguageOptions`. Состав и порядок записей upstream не меняются. В конец добавляется `{ label: "Русский (Russian)", value: "ru_RU" }`. `export const languageOptions` — `allLanguageOptions.filter`, множество разрешённых значений ровно `en_US` и `ru_RU`. `languages` по-прежнему `languageOptions.map((i) => i.value)` и равен `["en_US", "ru_RU"]`.
- В `shared/utils/date.ts` добавляется `import { ru } from "date-fns/locale/ru"` и свойство `ru_RU: ru` в объект `locales`. Остальные импорты и ключи остаются.
- Клиентский и серверный `fallbackLng` не меняются.

## Правила перевода

- Переводится значение из `en_US`. Ключ копируется байт в байт. Если значение отличается от ключа, переводится значение.
- Форма `_0` — один (1, 21, 31…). Форма `_1` — два–четыре (2–4, 22–24…). Форма `_2` — остальные числа (0, 5–20…). Ключ без суффикса совпадает с `_0`, ключ `_plural` совпадает с `_2`, кроме случаев, где русские формы «один» и «много» совпадают по слову. Суффиксы `_one`, `_few`, `_many` не добавляются.
- В значении остаются без перевода: плейсхолдеры `{{...}}` с теми же именами, что в ключе; сочетания и имена клавиш `⌘`, `Ctrl+`, `Cmd+`, `Shift+`, `Alt+`, `Opt+`; фрагменты в обратных кавычках; URL `http://` и `https://`; HTML-теги. Имя Outline не переводится.
- Первый проход закрывает весь каталог: каждый ключ `en_US` есть в `ru_RU`, значение непустое.

## Как обновлять

```text
git fetch upstream --tags
git merge <tag>
```

Тег вида `vX.Y.Z` берётся из `git ls-remote --tags upstream`. Merge идёт в `main`. После merge переводятся ключи, которые есть в `en_US` и отсутствуют в `ru_RU`, и для новых счётных ключей добавляются `_0`, `_1`, `_2`. Должны пройти `shared/i18n/ruLocale.test.ts`, `shared/i18n/translations.test.ts`, `app/utils/i18n.test.ts`, `app/utils/language.test.ts` и `shared/utils/language.test.ts`. Эти тесты уже знают только про `en_US` и `ru_RU`, поэтому следующий тег может задеть их, если upstream снова расширит список языков в самих тестах.
